# 起動コマンド一覧（アプリ / API）

開発でよく使う起動は次のパターン。Cursor に「Windows でローカル DB で起動して」などと頼むと、`.cursor/rules/startup.mdc` に従い同じコマンドを実行する。

Android は **Flavor 必須**（`staging` = テスト、`prod` = 本番）。`--flavor` と `--dart-define=FLAVOR` / `APP_ENV` はセットで渡す。

| # | やりたいこと | 作業ディレクトリ | コマンド |
|---|--------------|------------------|----------|
| 1 | **アプリ（Windows・テスト API）** | `C:\dev\tag_reader_app` | `flutter run -d windows --dart-define=FLAVOR=staging --dart-define=APP_ENV=test` |
| 2 | **アプリ（Android 実機・テスト）** | `C:\dev\tag_reader_app` | `flutter run --flavor staging --dart-define=FLAVOR=staging --dart-define=APP_ENV=test -d A142` |
| 2b | **アプリ（Android 実機・本番）** | 同上 | `flutter run --flavor prod --dart-define=FLAVOR=prod --dart-define=APP_ENV=prod -d A142` |
| 3 | **API（ローカル DB）** | `C:\dev\TagReaderApi` | `dotnet run --launch-profile http` |
| 4 | **API（本番 DB）** | `C:\dev\TagReaderApi` | `dotnet run --launch-profile http-production` |
| 5 | **アプリ（Windows・ローカル API）** | `C:\dev\tag_reader_app` | `flutter run -d windows --dart-define=APP_ENV=local` |

ローカル API の URL は `http://localhost:5262`。Azure 接続先は Flavor で固定（コード手書き換えしない）。

---

## 1. アプリ: Windows デスクトップ

詳細: [Windowsでの起動方法](Windowsでの起動方法.md)

```powershell
cd C:\dev\tag_reader_app
flutter pub get
# Azure テスト API（標準）
flutter run -d windows --dart-define=FLAVOR=staging --dart-define=APP_ENV=test
# ローカル API
# flutter run -d windows --dart-define=APP_ENV=local
```

- RFID / Bluetooth タグリーダーは使えない（UI・API 疎通向け）
- Windows では `--flavor` は不要（`FLAVOR` / `APP_ENV` の dart-define のみ）

---

## 2. アプリ: Android 実機

詳細: [タグリーダー実機テスト手順](タグリーダー実機テスト手順.md)

```powershell
cd C:\dev\tag_reader_app
flutter devices
# テスト環境（標準）
flutter run --flavor staging --dart-define=FLAVOR=staging --dart-define=APP_ENV=test -d A142
# 本番環境（明示時のみ）
# flutter run --flavor prod --dart-define=FLAVOR=prod --dart-define=APP_ENV=prod -d A142
```

- 端末 ID: `A142` / `00067245O000580`
- applicationId: staging=`com.ohmiyakouki.tagreaderapp.staging` / prod=`com.ohmiyakouki.tagreaderapp`（同一端末に併存可）
- Cursor 実行構成: 「タグアプリ：テスト環境」「タグアプリ：本番環境」

---

## 3. API: ローカル DB

```powershell
cd C:\dev\TagReaderApi
dotnet run --launch-profile http
```

- `ASPNETCORE_ENVIRONMENT=Development`
- 接続先: `appsettings.Development.json`（例: `localhost\SQLEXPRESS` の `OOMIYADB`）
- 確認: `GET http://localhost:5262/api/environment` → `"environment":"Development"`

`dotnet run` のみ（プロファイル未指定）も Development（ローカル DB）になる。

---

## 4. API: 本番 DB

```powershell
cd C:\dev\TagReaderApi
dotnet run --launch-profile http-production
```

- `ASPNETCORE_ENVIRONMENT=Production`
- 接続先: `appsettings.Production.json`（社内本番 SQL Server）
- 確認: `GET http://localhost:5262/api/environment` → `"environment":"Production"`
- **書き込み系の操作は慎重に**（本番データを触る）

## よくある組み合わせ（自然言語 → やること）

| 言い方の例 | 起動するもの |
|------------|--------------|
| 「Windows でローカル DB で起動して」 | API **3** + アプリ **5** |
| 「Windows で起動して」 | アプリ **1**（staging） |
| 「実機で起動して」 | アプリ **2**（staging） |
| 「本番 Flavor で実機起動」 | アプリ **2b** |
| 「API だけローカルで」 | API **3** のみ |
| 「API を本番 DB で」 | API **4** のみ |

API とアプリは **別ターミナル** で長時間起動する（どちらかが落ちると疎通できない）。
