# 大宮タグリーダーアプリ — 機能説明資料（AI・プレゼン生成向け）

## この文書の使い方

- **目的**: 別のAIやプレゼンツールにこのファイルを読み込ませ、スライド構成・話すポイント・デモシナリオを生成させるための**一次情報**です。
- **推奨プロンプト例**: 「添付の `アプリ機能説明_AIプレゼン用.md` に基づき、聞き手は現場担当者とIT責任者、15分想定でスライド10枚程度の構成案と各スライドの箇条書きを日本語で出力してください。」

---

## 1. アプリ概要

| 項目 | 内容 |
|------|------|
| 名称 | 大宮タグリーダーアプリ（Flutter `MaterialApp` のタイトルは「タグリーダー」） |
| 用途 | ハンディ型 RFID（ICタグ）リーダーと連携し、タグの読取・商品照合・ステータス更新、受付伝票の参照・紐付け、在庫確認を行う業務アプリ |
| 主な利用シーン | 倉庫・店舗・整備現場などでのタグスキャン、台帳更新、伝票作業、在庫状況の確認 |
| バックエンド | TagReaderApi（ASP.NET 等）経由で SQL Server 上の台帳と連携。接続先は開発（ローカル）/本番（Azure 等）で切替可能 |

---

## 2. 技術・実行環境

- **フレームワーク**: Flutter（Dart 3）
- **対応OS**: Android / iOS を主対象（TSS RFID SDK ネイティブブリッジ）。Windows 等では RFID 未接続でも API テストが可能な画面あり
- **ハードウェア**: Bluetooth 経由で TSS 系 RFID リーダー（R-5000 / SR7 / DOTR 等、コード上は `ReaderFamily` で機種差を吸収）に接続
- **通信**: `http` パッケージで REST API。タイムアウト約15秒
- **ローカル保存**: `shared_preferences`（接続デバイス名、担当者コード、保管場所、電波出力、ハードウェアトリガーモード等）

---

## 3. 画面マップ（ホームからの入口）

ホームは **2×2＋α のメニュータイル** と **出力モード（電波距離プリセット）** から構成。

| メニュー | 遷移先の主機能 |
|----------|----------------|
| タグリーダー接続 | BLE スキャン、ペアリング済み一覧、接続/切断、ファームウェア表示 |
| ICタグ読取・更新 | インベントリ読取、一覧、ステータス変更、サーバ送信 |
| 設定 | 担当者コード、保管場所、本体トリガー動作、出力詳細（dBm） |
| 伝票読み込み | 伝票一覧の絞り込み種別を選び一覧へ |
| タグEPC読取・表示（テスト） | DB 照合なしで EPC を一覧表示（開発・検証用） |
| 在庫表示 | API 集計による在庫一覧・カテゴリ/検索・個体明細へドリルダウン |

**ヘッダー表示**: タイトルに接続 DB ラベル（本番DB / ローカルDB）、担当者名、保管場所、接続中デバイス名を表示。

## 4. 機能詳細

### 4.1 タグリーダー接続

- ペアリング済みデバイス一覧の表示、BLE スキャンで周辺機を発見
- 接続成功時にデバイス情報を保存し、ホームに反映
- 切断・リンクロスト時に保存をクリア
- Android / iOS では Bluetooth 権限リクエスト
- アプリから一覧削除（Android は OS ペアリング解除も含む想定）

### 4.2 出力モード・電波強度（ホーム & 設定）

- **ホーム**: 「手元 / 近距離 / 中距離 / 遠距離」のプリセット選択と「適用」。接続時はリーダーへ dBm 相当を反映、未接続時は保存のみ
- **設定 → 出力詳細設定**: dBm を手動調整（`RadioPowerScreen`）

### 4.3 ICタグ読取・更新（メイン業務）

- **読取開始/停止**: 実機では `TagReaderService` のインベントリ API。ストリームで EPC を受信
- **ハードウェアトリガー**: 本体の読取ボタンに連動。設定したモード（切替式・時間式・長押し式）で読取の開始/停止を制御。機種（SR7 等）により強制トグルになるケースあり
- **一覧表示**: EPC、商品コード・番号、商品名、ステータス（バッジ）、送信済み表示
- **照合**: 実機で API 利用可能な環境では `GET /api/products?epc=...`。オフライン寄りでは `TagLedgerCache`（同梱 JSON）も参照
- **操作**:
  - **ダブルタップ**: 送信候補の選択/解除（視覚的に強調表示）
  - **長押し/右クリック**: ステータス変更ダイアログ。変更後、その行を送信候補に追加
- **ステータス候補**: ＯＫ、清掃中、整備中、修理中、貸出中、廃棄、在庫、予約、自社使用、不明 など（DB `tag_mode2` に整合）
- **送信**: `POST /api/product-updates` で ICタグ台帳更新と `tag_table4` へのログ INSERT。担当者コード（従業員コード）を付与
- **テスト**: API 接続時のみ「ランダムに1件読み取り」（`GET /api/products/random?count=1`）で一覧に追加可能

### 4.4 設定

| 項目 | 内容 |
|------|------|
| 担当者コード入力 | API で氏名解決。ホーム表示や更新送信に利用 |
| 保管場所選択 | ICタグ更新フローで参照・表示に利用 |
| タグリーダー本体の読み取りボタン設定 | 切替式・時間式・長押し式、時間の秒数 |
| 出力詳細設定 | 電波強度の数値指定 |

### 4.5 伝票読み込み〜一覧〜紐付け

- **伝票読込メニュー**:
  - **担当伝票のみ表示**: 設定済み担当者コードでフィルタ（未設定なら案内）
  - **全伝票一覧**: 本番DB では最新10件・転記済み除外などのフィルタ。開発時はランダム10件のテストモードあり
  - **来店伝票一覧**: 来店系伝票に絞り込み
- **伝票一覧**: 受付台帳 API から最大10件取得。担当者名・商品名はキャッシュで補完
- **伝票・商品紐付け画面**: 伝票詳細から遷移。RFID で読んだ商品をリストに追加しチェック、API/キャッシュで商品情報を解決（モックデータ併用の開発経路あり）
- **選択伝票の一括送信**: 紐付け済みタグを `POST /api/reception-slips/{receptionNo}/link-tags` で送信。ICタグ台帳を「貸出中」にし、`tag_table3` に受付番号付きで記録する（既存 C# 納品転記が番号を拾う）

### 4.6 タグEPC読取・表示（テスト）

- インベントリで受け取った PC+UII、RSSI、チャネル、時刻などを一覧
- メモリバンク読取（`read_tag_data`）があれば併記
- **商品DB との照合は行わない**（アンテナ・タグ検証用）

### 4.7 在庫表示（Zaicon 系 UI）

- `GET /api/products/inventory` で商品単位の集計一覧
- テキスト検索、カテゴリグリッド（Zaicon 互換のカテゴリマッチ）
- ステータス別バッジ（例: ＯＫ、清掃中、在庫系の件数表示）
- 行タップで **同一商品コードの個体一覧**（`GET /api/products/inventory/units?code=`）

## 5. バックエンド API（アプリが呼ぶ主なエンドポイント）

| 用途 | メソッド・パス（概念） |
|------|-------------------------|
| 環境表示 | `GET /api/environment`（本番/開発の表示用） |
| 担当者 | `GET /api/employees?code=`、`GET /api/employees/all` |
| 商品・EPC | `GET /api/products?epc=`、`GET /api/products/random?count=` |
| タグ更新 | `POST /api/product-updates` |
| 在庫 | `GET /api/products/inventory`、`GET /api/products/inventory/units?code=` |
| 伝票 | 受付台帳取得（フィルタ付き。実装は `ApiClient.fetchReceptionSlips`） |

※ 正確なパス・パラメータは `lib/api/api_client.dart` および TagReaderApi 側を参照。

## 7. 制約・未実装・注意事項（プレゼンで触れると信頼感が出る点）

- **プラットフォーム差**: Windows 等では `kUseApi` が true の場合と、モバイル実機で API を使わない構成があり、同一機能が「利用可能/不可」で分かれる画面がある（例: 伝票一覧は API 接続時、ランダム読取テストも API 接続時）
- **本番DB**: 本番接続時は読み取り専用扱いの設計がコードコメントにある（誤更新防止）
- **伝票の選択送信**: 実装済み（ローカル／書き込み可 DB のみ。本番 ReadOnly ではブロック）
- **将来機能（別ドキュメント記載）**: EPC・商品コード・番号からの新規タグ登録フローは ToDo

## 8. プレゼン用の論点リスト（スライド種子）

1. **課題**: 紙・バーコードに比べた RFID のメリット（一括読取、誤読低減など）— 必要なら一般論として補足
2. **全体像**: リーダー ↔ アプリ ↔ API ↔ 社内DB
3. **1日の流れ**: 接続 → 担当者/保管場所設定 → 読取・更新送信
4. **コア機能**: ICタグ読取・更新（一覧、ステータス、送信）
5. **伝票連携**: 一覧の見方、紐付け画面の位置づけ、送信未実装の開示
6. **在庫確認**: 集計→個体ドリルダウン
7. **運用**: 出力モード・本体トリガー設定（現場の使い勝手）
8. **開発/検証**: EPCテスト画面、ランダム読取、ローカルAPI
9. **セキュリティ・環境**: 本番/開発の切替、タイムアウト
10. **ロードマップ**: 伝票送信実装、新規タグ登録など

## 9. 用語ミニ辞書

| 用語 | 説明 |
|------|------|
| EPC | RFID タグの識別子。本システムでは DB の `tag_id2` と対応 |
| インベントリ | リーダーが周波数を走査しタグ ID を列挙する読取モード |
| ICタグ台帳 | タグ ID と商品・ステータスを紐づけるマスタ系テーブル |
| tag_table4 | タグモード変更などのログテーブル |
